QUESTION 4 - STRENGTHS AND WEAKNESSES OF THE MED-AI PROJECT BOARD


SECTION A - STRENGTHS

  - Dashboard, Kanban, and Gantt combined in one tool. The site's own
    meta description confirms this scope ("Dashboard, Kanban & Gantt
    Chart"), and the navigation shell lists Overview, a task/Kanban
    view, and a Gantt Timeline view together. Many free PM tools
    (Trello, plain GitHub Projects) offer only a Kanban board and
    nothing else; having all three views in one place is a real
    design advantage for a small team that wants one place to look.
  - Almost no barrier to use. It is a single public URL - no sign-up,
    no install, nothing to configure before viewing. That was
    confirmed directly: navigating straight to the project routes
    (overview, board, gantt, members, activity) returned content
    without hitting a login wall. Sharing the whole board with a
    team, or with a lecturer, is one link.
  - Unlimited customisation because it is built in-house. Unlike
    Jira, Trello, or GitHub Projects, this tool is not constrained by
    a vendor's data model - the team that built it can add any field,
    any view, or any workflow rule they want, with no plan tier
    gating a feature behind a paywall.
  - Zero running cost at small scale. It is hosted on Vercel's
    platform and, at a single small project's traffic level, likely
    costs nothing to run (Vercel's own free tier covers small Next.js
    deployments) - a fair strength for a student or internal tool,
    though the exact hosting bill was not checked in this session.

SECTION C - WEAKNESSES THAT STILL NEED VERIFICATION

These are hypotheses, not findings. Each is a typical gap in a
demo-grade, in-house-built board, and each needs the stated check
before it can be reported as confirmed.

  - Data may be hard-coded with no real database, so changes could be
    lost on reload. How to check: run Q3's Step 2 (drag a card, press
    F5, see if it reverts).
  - No login and no permissions, so anyone might be able to edit, not
    just view. This session confirmed viewing needs no login; it did
    not confirm whether editing is also open. How to check: attempt
    to edit a card without any sign-in step and see if the change is
    accepted.
  - No change history and no comments on cards. How to check: open a
    card (Q3 Step 5) and look for a history or comment section.
  - No notifications when a card changes state. How to check: change
    a card's state in one browser session and see whether a second,
    simultaneous session is notified or has to refresh manually.
  - No Git integration, so a card may not close automatically when
    its pull request merges, and the board could lag behind the real
    code. This is where GitHub Projects (Section E) is structurally
    ahead, since that link is native there. How to check: look for
    any commit or pull-request reference on a card, or a webhook
    settings page under "Cai dat" (Settings).
  - The Gantt chart may have no dependency links and no critical
    path. How to check: Q3 Step 6, since the Gantt route's underlying
    data could not be inspected without running its client-side
    script.
  - No WIP limits, so the board could degrade into a long to-do list
    and lose its ability to reveal bottlenecks. How to check: look
    for a numeric cap shown on any column header.
  - No acceptance-criteria field on cards. This is the most serious
    possible gap from a requirements-engineering standpoint if
    confirmed, because without acceptance criteria nobody can say
    when a story is actually finished. How to check: Q3 Step 5, open
    a card and read its full field list.
  - No CSV or PDF export. How to check: look for an export option in
    Settings or on the board/Gantt toolbar.
  - Layout may break on small screens. How to check: Q3 Step 4,
    resize to 375 px and observe.

In one sentence each: Med-AI Project Board is best as a fast, no-setup
way to present a combined Dashboard/Kanban/Gantt view to people who
just need to look at it; GitHub Projects is best for a team that is
actually writing code and wants its board to track the real state of
that code, at zero cost, even though it must be assembled by hand
from generic building blocks.
